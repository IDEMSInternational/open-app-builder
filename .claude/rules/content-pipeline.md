# Content architecture: sheets → JSON → runtime (verified Aug 2026)

## Pipeline

Google Sheets are downloaded as xlsx (`<deployment>/tasks/gdrive/outputs/sheets/`), converted by
`packages/scripts/src/lib/app-data/convert/` into `<deployment>/app_data/sheets/<flow_type>/…json`, then
copied to `src/assets/app_data/` by `yarn workflow populate_src_assets` (also run by `yarn prepare` inside
`yarn start`). Regenerate without re-download: `yarn workflow sync_sheets --skip-download` then
`populate_src_assets`.

**Cache:** parses are cached in `<deployment>/tasks/template/cache/FlowParserProcessor/`, keyed by md5 of the
input plus a hardcoded `cacheVersion` in `convert/processors/flowParser/flowParser.ts`. Parser code changes do
not invalidate it — delete the folder first. `shouldUseCachedEntry` returns false for `data_pipe` and
`generator` flows, so those are always re-parsed.

## Flow types and variable namespaces

- `template` — UI pages: rows of typed components. `data_list` — static data (incl. the `lifecycle_actions`
  subtype). `global` — constants and field defaults.
- `@local` template-scoped (`set_variable`); `@fields` persisted in browser localStorage
  (`rp-contact-field.` prefix, written by `set_field`,
  `src/app/shared/components/template/services/template-field.service.ts`); `@global` constants;
  `@data` data lists; `@item` inside `data_items` filters.

## Finding the sheet to edit

Every generated flow JSON ends with a `_source` block: workbook name, path and Google Sheets `url`
(tab = `flow_name`). For duplicated flows `_source` shows the *winning* workbook.
`<deployment>/source_data/sheet_json/_metadata.json` lists all copies. `source_data` files have no inline
`_source`.

## Duplicate flows / local overrides

Same `flow_name` in two workbooks logs "Duplicate flows found" but resolves **last-wins** by
`config.google_drive.sheets_folders` order in the deployment `config.ts` (`flowParser.ts` `postProcess` →
hashmap overwrite). Copying a shared template into a deployment workbook under the same `flow_name` and
editing the copy is the established override pattern; expect one benign duplicate-flow log line per copy.

## Globals resolution

Several global sheets may declare the same constant; they apply in `contents.json` load order — **later
wins** (`initialiseDefaultFieldAndGlobals` in
`src/app/shared/components/template/services/template.service.ts`). `declare_field_default` writes only if
the localStorage key is null.

## Actions

Authored as `trigger | action_id: args | params`; parsed at sync time by `parseAppDataActionString`
(`convert/utils/app-data-action.utils.ts`). Unknown triggers are silently rewritten to `click`. Runtime
reads parsed JSON only, so a component expecting a new trigger gets nothing if the content was generated by
an older parser.

## App startup / onboarding launch

`app.component.ts` init → `initialiseDefaultFieldAndGlobals` → `handleLaunchActions`
(`src/app/shared/services/lifecycle-actions/lifecycle-actions.service.ts`) reads data list
`lifecycle_actions/launch_actions.json`, sorts by priority, evaluates `condition_list`, runs actions
(typically fullscreen `pop_up`s; those with `waitForDismiss` run sequentially). Onboarding steps are gated
like `@fields.user_mode && !@fields.onboarding_x_completed && @global.has_onboarding_x`.
